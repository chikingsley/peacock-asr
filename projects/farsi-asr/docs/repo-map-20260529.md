# Persian ASR — Repo Map & Mental Model (2026-05-29)

Read-only inventory to build a mental model of the project and plan cleanup.
Nothing was moved or deleted in producing this.

## The one-paragraph mental model

The project is a **data funnel** feeding **two parallel training tracks** (Omni via
fairseq2, Parakeet via NeMo), then a **benchmark/compare** stage. Raw audio is
standardized, scored and human-verified (Scribe) for quality, filtered into recipe
selections, exported to a trainer-specific format, trained, and evaluated. The code
*flow* is coherent; the mess is in (a) two overlapping code packages, (b) chaotic
naming + no lineage in `data/`, and (c) scattered/duplicated model artifacts.

```text
raw/ ─► canonical/ ─► curation/ (omni_scores + scribe_jobs) ─► selection/candidate-manifests/
        ─► training/scribe-verified/ (filtered manifests) ─► training/omnilingual/ (parquet)
        ─► [TRACK A: persian-train-omni] ─► runs/ ─► models/omnilingual/
        ─► [TRACK B: persian-finetune-parakeet*] ─► parakeet/runs/ ─► models/parakeet-ctc-109m/
        ─► benchmarks/suites/ ─► canonical-benchmark-comparison.sqlite
```

## Why it feels "out of hand" — root causes

### 1. Two overlapping code packages (the biggest one)

`src/` has three packages, but `persian_asr_dataset` and `persian_omnilingual_asr`
**duplicate the same responsibilities**:

- two `ledger.py` (LedgerSample + schema + connect) — schema can drift
- two `ingest.py` entry points (`persian-dataset-ingest` vs `persian-ingest-corpus`)
- two `export_nemo_manifest.py` (~90% identical)
- `maybe_normalize` lives in `persian_asr_dataset/vendor/` but is imported across both
- inconsistent `PROJECT_ROOT` resolution (`parents[2]` vs `parents[3]`)

This is almost certainly why the code half feels tangled: there are two half-built
"spines" for the same pipeline.

### 2. `data/` naming chaos + no lineage

- experiment-variant explosion in `training/scribe-verified/`:
  `max-train-now`, `max-train-supported-script`,
  `max-train-metric-supported-script-rescue-text-asr-recovery-held-possible-v3-full-20260527`…
  progressively longer, cryptic, no metadata explaining the diff.
- ambiguous scribe jobs: `scribe-20-per-dataset` vs `scribe-20-per-source` vs `…-cvfix`.
- raw↔canonical name drift: `thomcles_persian_omni`→`thomcles`, `neyshekar_v3_asr_aligned`→`neyshekar`.
- no lineage metadata linking a filtered output back to its inputs / filter rule.
- same recipe appears as both a `selection/` manifest and a `training/omnilingual/` export.

### 3. Scattered / duplicated model artifacts (~10G waste)

- "best" checkpoints exist in both `runs/*/checkpoints/step_*/model/` and
  `models/omnilingual/checkpoints/*` (no symlinks).
- `*_best` vs `*_final` checkpoints likely identical.
- 5 stale Omni runs keep logs but have **no checkpoints** (early-stopped/crashed).
- optimizer state ~2.4G per checkpoint (only needed to resume).

### 4. Dead weight & hardcoded paths

- `vendor/mobius/` (894M) is unrelated to Persian ASR.
- `data/archive/parakeet/` 7G stale; `parsvoice` stub; `mozilla_data_collective` 23G (verify if used).
- hardcoded absolute paths: `dataset_prep/curated.py` DEFAULT_DATASET_ROOT/OUTPUT_ROOT,
  `dataset_prep/text_audit.py` fairseq2 cache path (`/home/simon/.cache/fairseq2/...`) — non-portable.

### 5. Benchmarks & scripts rough edges

- dated suite folders duplicate `canonical-tests/` (~1.4G).
- `scripts/run_scribe_v2_canonical_suite.py` duplicates `persian-benchmark-suite`.
- standalone scripts not installed as entry points; `.fairseq2-assets/` untracked.
- ~30 console entry points, many one-off/legacy with no "active vs archived" signal.

## Proposed cleanup — tiered (react to this; nothing done yet)

### Tier 0 — safe, reversible, do anytime (~17G + tidy)

- Add to `.gitignore`: `.fairseq2-assets/` (done-list).
- Delete `data/archive/parakeet/` (7G stale) and `data/raw/parsvoice/` (stub) — **after you confirm**.
- Delete the 5 stale checkpoint-less Omni runs in `runs/` (~150M clutter).
- Strip `optimizer/` from frozen/old checkpoints you won't resume (~2.4G each).
- `du`-verify and decide on `vendor/mobius/` (894M, unrelated) and `data/hf-cache/`.

### Tier 1 — disk + clarity, low risk

- De-duplicate model checkpoints: keep `models/omnilingual/checkpoints/` as the canonical
  export location; drop redundant copies from frozen `runs/`. Document run→model mapping.
- Verify `data/raw/mozilla_data_collective/` (23G) usage; archive or drop if unused.
- Collapse dated benchmark suite folders into `canonical-tests/` + metadata.

### Tier 2 — structural (the real fix), needs care

- **Merge the two packages into one spine.** Single `ledger`, single `ingest`, single
  `export_nemo_manifest`, single `paths.py`, one `text_normalization` module. Pick
  `persian_asr_dataset` as the shared core; have the Omni/Parakeet packages depend on it.
- Remove hardcoded absolute paths; route everything through `paths.py` + env override.
- Rationalize the ~30 entry points: tag active vs legacy; drop dead ones.
- Introduce **lineage metadata**: every derived dataset records its inputs + filter rule,
  and adopt a single, documented naming scheme (kill the `max-train-…-v3-full` sprawl).

### Leave alone

- `data/raw/` and `data/canonical/` structure (logical; just naming drift).
- `benchmarks/suites/` per-model/per-dataset layout (sound).
- The data-funnel concept itself — it's correct; it needs naming + lineage, not a redesign.
